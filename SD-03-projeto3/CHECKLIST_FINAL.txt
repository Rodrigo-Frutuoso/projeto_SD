 REQUISITOS DO ENUNCIADO
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[✅] 1. Servidor multi-threaded (modelo one-thread-per-client)
     - Thread principal aceita conexões
     - Thread secundária por cada cliente
     - Threads criadas com pthread_create()
     - Threads detached para libertar recursos

[✅] 2. Limite de 5 clientes simultâneos
     - Contador num_clientes_ativos implementado
     - Verificação antes de aceitar nova conexão
     - Rejeição quando limite atingido

[✅] 3. Protocolo OP_BUSY / OP_READY
     - OP_BUSY = 100 adicionado ao sdmessage.proto
     - OP_READY = 101 adicionado ao sdmessage.proto
     - Servidor envia mensagem de estado após accept()

[✅] 4. Cliente verifica estado do servidor
     - network_connect() recebe mensagem de estado
     - Mostra "Server busy. Try again later." quando OP_BUSY
     - Continua normalmente quando OP_READY

[✅] 5. Ficheiro de log server.log
     - Criado automaticamente pelo servidor
     - Modo append para não perder logs anteriores
     - Fechado corretamente ao terminar servidor

[✅] 6. Eventos registados no log
     - CONNECT: quando cliente estabelece ligação
     - REQUEST: quando cliente envia pedido
     - CLOSE: quando cliente fecha ligação

[✅] 7. Formato do log correto
     - <timestamp> <IP:porta> <event_type> [detalhes]
     - Timestamp obtido com gettimeofday()
     - Timestamp em segundos (UNIX epoch)

[✅] 8. Detalhes dos REQUEST no log
     - Opcode (OP_ADD, OP_GET, etc.)
     - Content type (CT_DATA, CT_MODEL, etc.)
     - Argumentos específicos (marca, modelo, ano, etc.)

[✅] 9. Gestão de concorrência - Mutex para log
     - log_mutex criado e inicializado
     - Lock antes de escrever no log
     - Unlock depois de escrever

[✅] 10. Gestão de concorrência - Mutex para clientes
     - clients_mutex criado e inicializado
     - Protege num_clientes_ativos
     - Lock em incrementos/decrementos

[✅] 11. Gestão de concorrência - Mutex para lista
     - list_mutex criado e inicializado
     - Protege acesso à struct list_t
     - Lock antes de invoke(), unlock depois

[✅] 12. Sem race conditions
     - Todos os recursos partilhados protegidos
     - Ordem consistente de locks
     - Testado com Helgrind (valgrind)

[✅] 13. Sem deadlocks
     - Nunca múltiplos locks simultâneos
     - Locks sempre libertados
     - Sem locks dentro de locks

[✅] 14. Sem memory leaks
     - Threads detached (recursos libertados)
     - Mutexes destruídos em network_server_close()
     - Testado com Valgrind
