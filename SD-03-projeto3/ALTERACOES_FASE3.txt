FUNCIONALIDADES IMPLEMENTADAS:
-------------------------------

✅ Servidor multi-threaded (modelo one-thread-per-client)
   - Thread principal aceita conexões em loop infinito
   - Para cada cliente, cria thread secundária (pthread_create)
   - Threads secundárias atendem pedidos do cliente até desconexão
   - Threads são detached para libertar recursos automaticamente

✅ Limite de 5 clientes simultâneos
   - Contador num_clientes_ativos protegido por mutex
   - Antes de aceitar: verifica se contador < 5
   - Se SIM: envia OP_READY, cria thread, incrementa contador
   - Se NÃO: envia OP_BUSY, fecha conexão

✅ Sistema de logging completo (server.log)
   - Regista CONNECT quando cliente estabelece ligação
   - Regista REQUEST quando cliente envia pedido (com detalhes)
   - Regista CLOSE quando cliente fecha ligação
   - Timestamps obtidos com gettimeofday()
   - Formato: <timestamp> <IP:porta> <evento> [detalhes]

✅ Gestão de concorrência com mutexes
   - log_mutex: protege escritas no ficheiro de log
   - clients_mutex: protege contador de clientes ativos
   - list_mutex: protege acesso à lista encadeada
   - Todos os acessos a recursos partilhados são protegidos

✅ Cliente inteligente
   - Recebe mensagem de estado após connect()
   - Se OP_BUSY: mostra mensagem e termina
   - Se OP_READY: continua normalmente

GARANTIAS DE CORREÇÃO:
----------------------

1. Exclusão Mútua:
   - Todos os acessos a recursos partilhados são protegidos
   - Lock sempre antes de aceder, unlock sempre depois

2. Ausência de Deadlocks:
   - Nunca fazemos lock de múltiplos mutexes simultaneamente
   - Ordem de locks é consistente quando necessário

3. Ausência de Race Conditions:
   - Contador de clientes sempre atualizado atomicamente
   - Escritas no log são serializadas
   - Lista encadeada nunca é acedida concorrentemente

4. Gestão de Memória:
   - Threads são detached (recursos libertados automaticamente)
   - Todos os mallocs têm free correspondente
   - Mutexes são destruídos em network_server_close()

5. Robustez:
   - Servidor nunca crasha, mesmo com erros de clientes
   - Todos os erros são tratados adequadamente
   - Fechos abruptos de clientes são geridos corretamente
